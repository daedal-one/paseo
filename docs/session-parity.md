# Session functionality and qualification

The redesigned Workspace uses the Host’s complete canonical Session contribution graph. Session controls, conversation rendering, pending interactions and introspection keep their existing owners. Browser, Electron and the iPhone carrier load that same interface; they do not maintain separate Session presentations. Native enrollment, networking and save/share operations remain platform responsibilities, described in the [canonical carrier README](../packages/app/modules/dsh-canonical/README.md).

Durable Work, Files and Memory are the main Workspace surfaces. A Work item can have linked Session executions; **Inspect execution** places the canonical Session beside its Work board on desktop. Expanding inspection preserves the same Session view, draft and selected Request. Phones prioritize the selected pane, with a direct return to Work. Desktop inline execution places canonical Chat and its composer above the selected inspector. Open full inspector expands that view while preserving the mounted Chat, inspector and composer; phone presentation uses one primary view. Context, Trajectory, Prompt & tools, Usage, Info and Events remain available. A historical Request selection opens its recorded prompt by default; the explicit Current Host prompt choice remains available.

This ledger distinguishes retained implementation from exercised behavior. Reusing the contribution graph closes the former custom UI’s missing-control and renderer gaps, but does not establish that every feature has passed end-to-end testing on every platform. Disabled Schedule UI and controls absent from the incumbent composition, including Session deletion and unarchive, are outside this baseline. Operator-added plugins require qualification with the selected Host graph.

## Remaining qualification

The final correction run passes both browser scenarios at 1440×900 and 390×844, plus 21 tests in the two affected component suites. The reviewer resolved the phone utility overlap and clipping, and accepted the corrected conversation, composer and Inspector arrangement. Visual reproduction is 75.45% against a 72% overall threshold. On 2 November 2026, Carlo accepted the real canonical transcript and Open full inspector control as intentional deviations from the approved image and authorized closing their regional visual objections. The recorded exception closes those design objections without changing the measured scores or the platform qualification limits below.

Keep browser, packaged desktop and physical-iPhone acceptance separate. The browser scenarios above cover the named flows; they do not certify every contribution, permission outcome, tool renderer, attachment operation or failure/recovery path. Validate operator-added plugins through the same graph rather than treating raw event visibility as renderer parity.

On iOS, qualify enrollment, canonical rendering, keyboard/composer interaction, reconnect/revocation, uploads, cancellation and save/share on a runnable Simulator or physical device. The narrow Electron smoke also leaves full Session workflows and native dialogs for platform acceptance. Android and other desktop operating systems have no qualification claim in this ledger.
