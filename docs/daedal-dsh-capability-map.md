# Daedal DSH capability baseline

This implementation handoff records the inspected DSH owners and the acceptance journey for each product area. Durable intent remains in the accepted `.specs/` documents. This inventory is source evidence; a generated method does not establish that a deployed host enables it or that the new frontend implements it.

The backend baseline is `6d05318ace06e41478c1e14335587a823c7240d7`; the frontend baseline is `8fffd9c1`, both on `codex/daedal-dsh`, inspected on 15 September 2026. The original DSH checkout remains separate on `master` at `d4d63d120a` with unrelated work and its existing running service. [The descriptor inventory](daedal-dsh-api-inventory.json) records 93 generated invocation descriptors from 16 selected owner packages, the 21 forwarded events, and 44 UI-prefixed packages. Direct/scoped variants are descriptors, not necessarily distinct user operations. Inventory rows retain their declaring source paths and line numbers; no wire schemas are copied into the frontend.

## Selected API and event delivery

`packages/api/remotes/src/client/index.ts` selects the generated Remote contributions. The inventory captures their namespace/method, invocation mode, streaming mode and source owner. Reuse those generated descriptors and codecs through Gateway; do not turn this JSON inventory into a runtime dispatcher or a second schema authority.

The forwarded-event allowlist is `packages/api/remotes/src/remote-events.ts`. Nineteen entries are ordinary emissions; `approval/request` and `user-questions/request` are scoped waterfalls. Gateway owns their result/next/rejection exchange. The internal `$events` stream establishes a generation only after host listeners attach; ordinary events are not durable replay. Session and workspace follow streams retain their own snapshots and cursors. A UI must not reconstruct durable state from missed ordinary emissions.

`workspaceFiles` is a read API at this baseline. `pluginInventory` and `skills.list` expose inventory, not arbitrary package or skill installation. Workflow, schedule, terminal, repository and memory-management namespaces are absent from the selected assembly. Their DSH services remain the starting point for the accepted backend extension tasks.

## Identity and platform decisions

The app stores references by authenticated host identity plus the native DSH workspace/session ID. Paseo agent IDs remain transition data and cannot become a new durable DSH identity. Each operation has one active writer path. Read-only comparisons may run against the bridge, but native and bridge mutations never run together for one action.

The iPhone upgrade retains `com.cavenditti.dshcompanion`, Apple team `PN9822BHR7`, Expo project `773deae9-13cd-4e9c-b34e-ddc936d13832` and the `dsh-companion` pairing scheme. The local desktop preview uses `one.daedal.dsh` and an ad-hoc signature; that does not establish signed distribution or notarization. macOS, iPhone and browser are the first qualification targets. Intel Mac, Windows, Linux and Android retain separate gates; no desktop-only control appears as a nonfunctional mobile action.

The frontend owns bounded caches, drafts, selection and presentation. DSH owns Session data, workspaces, process lifetime, permissions, provider credentials, settings, goals and scheduling. Managed desktop uses the existing private DesktopHost protocol and installation owner. End-user chat does not require Forge Spec or Intellect to run.

## Native integration decision gates

The portable Connection, Gateway, generated Remote assembly and shared Session/Workspace models are implemented through backend commit `4606541bbc`. The frontend installs the [DSH-owned portable distribution](../vendor/dsh/README.md), which retains the generated facade and shared Cordis/type identities without installing Host implementations. Native callers supply authenticated networking, cancellation, request identity, time zone and host-specific selection storage. The ordinary Web client uses the same domain implementations.

The authenticated Gateway stream carries its opening protocol version and durable Host/application activation identity. The native installer requires a paired Host id before it admits a connection generation or dispatches generated operations. Losing that generation cancels active operations and refuses late results without replay. Reading an identity over HTTP alone does not authorize a device or bind a later connection.

The Client journal refuses an opening header outside its supported logical Session format and refuses unknown required events before publishing snapshots, live entries or pages. Explicitly ignorable unknown events retain opaque payloads and metadata. The packed facade passed Metro iOS, Hermes compilation and restricted-runtime fixture execution, including incompatible-header refusal, an explicit reopen with the supported format, required-event refusal and retention of the accepted journal. Physical iPhone execution and an authenticated native Session remain unqualified.

Backend `3a5886064c` exposes authenticated Host capability discovery through `readHostCapabilities(rpc, expectedIdentity, signal?)` in the portable facade. It lists strict Host endpoints and distinguishes direct availability, a required receiver Context and unavailable dispatch prerequisites. Discovery invokes no resolver or business method and returns no provider credentials or local paths. The reader validates the entire snapshot and matches both Host and activation identities; its caller cancels the read when the admitted generation ends. The packed iOS fixture accepts capability metadata and refuses a mismatched activation. These are advisory facts; every actual invocation still applies current Host validation and permission checks.

The public DSH Web profile now qualifies this discovery through its real Loader composition in isolated Harness homes. The source-profile test authenticates the identity and capability queries, checks strict Session and Workspace endpoints, rejects unauthenticated requests and a forged request authority, and verifies stable Host identity with a new activation after restart. Browser-cookie continuity uses the same authority, including the OS-assigned port. This is real local HTTP/profile evidence; physical iPhone and authenticated native Session acceptance remain open. Capability assembly is private to the Gateway query.

The generated Host and Client descriptors now carry per-endpoint wire fingerprints, preserved by capability metadata version 3 alongside the authored business revision. The generator hashes the endpoint's resolved codec projection and wire fields, including transitive and recursive references. Source locations, type-symbol spelling, prose and unrelated endpoints are excluded. The checksum is conservative schema evidence; its absence means unverified compatibility, and equality alone does not establish business semantics or permission. Generated Remote calls carry both schema and business expectations. Native calls also bind the admitted Host activation and refuse absent evidence before sending. The Host rejects mismatches before Context or lookup resolution and rechecks the live descriptor after asynchronous preparation; a reload in that window cannot invoke the replacement method. Unary and stream refusals use `gateway/api-incompatible` without automatic command replay. The initial semantic revision is 1, with incompatible behavior changes declared by `@remoteRevision` on the owning DSH method. Unnegotiated legacy callers retain their existing route. Native generation admission requires an explicit Client selection from `selectRemoteCapabilities(endpoints)`, derived from the same generated contributions that the facade mounts. The installer checks the paired stream opening and reads capabilities for that exact activation before publishing readiness or forwarding events. Missing, unavailable, unverified or incompatible required endpoints refuse the generation. Optional endpoints remain visible in the admitted snapshot without blocking required features. Cancellation prevents late metadata from admitting a disconnected generation; every reconnect performs a fresh read.

The built facade passes authenticated HTTP/WebSocket admission and a generated settings call against the real DSH Web profile before and after restart. Actual package tarballs also pass Metro iOS, Hermes compilation and restricted-runtime Session/Workspace fixtures with admission enabled. These checks do not establish physical-device execution or authenticated native Session acceptance. The real cross-device flow remains open under `IFC:frontend/dsh-connection` and backend `IFC:frontend/daedal-dsh-client`. Gateway opening and capability metadata versions describe their own fields, independently of domain API schemas. The 93 compiled Client descriptors remain separate from the Host's live capability snapshot. The design and ownership baseline is accepted. The native-client task owns installation, application integration and the real cross-device acceptance flow.

DSH Connection implements opt-in device enrollment and independent revocation. The browser owner creates a challenge through `POST /api/connection/devices/enroll`; a phone claims it through the sole unauthenticated API exception, `POST /api/connection/devices/claim`, with the expected Host identity and device label. Host/Origin checks still apply. Challenges are short-lived, single-use and invalid after restart or plugin reload. A committed grant returns its bearer once; the Host persists only a digest and public metadata. Bearers cannot administer devices or fall back to browser cookies. The portable facade exports `claimDeviceEnrollment`, validates the returned Host and credential, omits ambient cookies, refuses redirects and never retries a claim.

Device HTTP requests and WebSocket streams retain revocation leases. Committed revocation cancels logical-stream signals immediately, closes active carriers and rejects future requests; other devices and browser sessions retain access. A cancelled asynchronous lookup cannot proceed into business execution. A command already accepted can still have an uncertain outcome. The real Web-profile test proves enrollment, single-use refusal, native bearer admission, credential survival across restart, stale-challenge refusal and active-stream revocation. The packed iOS fixture validates the portable claim using the native cancellation adapter. These remain local/profile and native-runtime fixture checks, not physical iPhone acceptance.

The actual app still needs QR presentation, host-scoped secure storage, authenticated transport adapters and discovery. A trusted host may return bounded discovery candidates, but each candidate needs separate identity and authorization. The accepted device-access task remains in progress until those user journeys pass on the iPhone. Existing Tailscale routes and loopback listeners remain the deployment boundary.

Commands retain confirmed success, confirmed rejection or unknown outcome. Lost responses never trigger an automatic mutation retry. The backend must expose deduplication/reconciliation where supported; otherwise the UI retains the uncertainty and requires a deliberate decision. Resolved interactions reject late replies. No compatibility workaround may discard required DSH events to fit a Paseo timeline.

## Native build requirements

The packed Gateway service keeps Cordis as a shared dependency. Cordis's normal ESM artifact contains class static blocks; the Expo 54 Babel pipeline requires `@babel/plugin-transform-class-static-block` before its other class transforms. The app declares that transform directly and applies it before the Expo preset's class-property transforms, following the [Babel ordering requirement](https://babeljs.io/docs/babel-plugin-transform-class-static-block). This is a syntax transform, not a runtime implementation of browser APIs.

Pass `createDshAbortController` as the controller factory to both Connection and Gateway. It adds abort reasons and `throwIfAborted()` to DSH-owned controller instances while retaining React Native's cancellation events and leaving globals and prototypes unchanged. Gateway releases composed-signal listeners at operation completion and does not require `AbortSignal.any()`. Native bundle checks remain separate from authenticated session and physical-device acceptance. Expo already supplies its URL implementation through `whatwg-url-without-unicode`; native probes must use that implementation rather than substitute Node's URL class.

## Work ownership

Backend accepted tasks are `daedal-dsh-native-client`, `daedal-dsh-device-access`, `daedal-dsh-host-operations`, `daedal-dsh-configuration-workflows` and `daedal-dsh-desktop-runtime` under `.specs/tasks/`. No missing control in the map is permission to add an independent frontend execution server.

## Application runtime ownership

`packages/app/src/dsh/runtime.ts` composes the installed Client distribution into one disposable Cordis root per Host. It mounts the generated Remotes and shared Session/Workspace services, selects essential endpoint requirements from their generated descriptors and uses the native cancellation adapter. Callers supply authenticated networking, Host identity, current time zone and already hydrated Host-specific navigation. Returning a runtime does not indicate a connected Host; the admitted generation remains the readiness authority. Supervised read streams wait for initial admission and recover after a lost generation. Commands retain single-attempt dispatch and explicit outcome uncertainty.

The existing application screens still use the transitional companion bridge. Native enrollment/storage, transport selection and Session presentation must be connected to this runtime before native UI acceptance. The native-client task remains in progress.

## Native Session search ownership

The opt-in Host directory uses the shared `ISessions.search` phrase operation and keeps snippets local to the open search view. Generated optional admission gates `session/search`; the Host must also enable its search provider. A refused search shows a retryable failure, distinct from no matches. The shared 20-result bound and `hasMore` guide query refinement. Each explicit result open calls `ISessions.loadSummary` before existing conversation navigation, so an off-page identity becomes addressable without copying Session metadata or replacing the followed list. Absence is a current list observation, not proof of durable deletion. Query edits, view closure and Host generation changes cancel reads and refuse late navigation; reconnect never repeats search. The [Phase 4 task](../.specs/migration/04-sessions-and-interactions.spec.md) records platform qualification and remaining release gates.

## Native fork recovery ownership

The shared Host runtime exposes a durable fork owner while visible fork controls remain hidden. Optional generated `session/forkTo` uses a fresh child identity retained with its exact source and anchor before one atomic storage claimant dispatches. Unknown outcomes survive restart and cannot be reset or resent. Explicit shared summary reads can offer the exact current child and parent for adoption; this does not confirm the original request or anchor. Workspace membership is observed separately, with a pending baseline distinct from no membership. Title changes, attachment repair and opening history require separate actions. Closing a review cancels its reads, while dispatched mutations retain their owner. The [Phase 4 task](../.specs/migration/04-sessions-and-interactions.spec.md#native-fork-recovery-qualification) records qualification and remaining controls.
