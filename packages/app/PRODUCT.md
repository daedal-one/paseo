# Daedal workspace

<!-- impeccable:product-schema 1 -->

## Platform

web

The same canonical interface runs in a browser, the desktop carrier and the iPhone carrier. Native carriers own connection, credential and platform-file operations. iPhone is the first mobile target.

## Users

People who delegate work to agents and need to review the result and understand how it was produced. A more specific market or audience has not been established.

## Product Purpose

Keep durable Work, Files and reviewed Memory together in a Workspace. Session executions implement Work; they remain accessible for conversation, intervention and detailed inspection without becoming the primary unit of organization.

## Positioning

The product combines durable work with extensive visibility into execution: recorded context, prompts, tools, trajectory, usage, environment, events and the existing rich Session interactions. Preserving that understanding is a product requirement.

## Operating Context

Users select a Workspace, create or revise a Work brief, start or link executions, review files and memory, and inspect or steer Sessions. Work and its captured execution brief survive navigation and restart. Desktop inspection can sit beside the Work board and expand for deeper reading; phones prioritize one selected pane.

## Capabilities and Constraints

Reuse the complete existing Session interface and its contribution owners. Retain rich transcript and tools, drafts, queue operations, approvals, questions, plans, goals, children, terminal, file previews, plugins, export and introspection. Do not replace those capabilities with raw data or a link to another interface.

Durable Work states and transient Session activity have distinct meanings. Display actual source facts and explicit unavailable readings. Workspace navigation does not implicitly create a Session. Uncertain mutations retain their identity and relevant user intent.

Private backend implementation and harness specifications are outside public frontend artifacts. Browser testing, desktop execution and physical-iPhone qualification are separate evidence. Android is not the current mobile release target.

## Brand Commitments

The product name is daedal. Interface text is direct and uses Workspace, Work, Files, Memory and execution consistently. The selected visual composition is recorded in the surface brief and its approved comp.

## Evidence on Hand

The approved comp is `.impeccable/mocks/dispatch-board-beside.webp`. Local review captures use a synthetic Sample workspace with real stored Work and a recorded-model execution. `../../docs/session-parity.md` identifies retained capabilities, completed checks and remaining platform limits. No customer, performance or production-release claims are established by these examples.

## Product Principles

- Durable work leads; executions explain how it happens.
- Preserve detailed Session understanding and intervention.
- Keep one authoritative owner for every Session and interaction.
- Use compact, readable layouts with stable drafts and selection.
- Distinguish implemented behavior from verified platform behavior.
